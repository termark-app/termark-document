# SSH 客户端保存密码和私钥安全吗？

把服务器密码、私钥和跳板机凭据交给一个 SSH 客户端之前，最重要的问题不是“它用了什么营销术语”，而是下面四件事：

1. 敏感字段是否明文落盘？
2. 本地解密密钥放在哪里？
3. 同步到云端之前是否已经加密？
4. 服务端能不能恢复你的明文数据？

“银行级加密”“军工级安全”都无法替代这些具体答案。

## 哪些数据应该被当成敏感信息

至少包括：

- SSH 密码和私钥内容；
- 私钥口令；
- 跳板机与代理凭据；
- 同步密码；
- API Key；
- 其他连接密钥。

主机地址、资产名称和分组也可能暴露内部网络结构。不同组织对它们的敏感级别定义不同，但密码和密钥不应以明文保存在普通数据库或配置文件中。

## 本地加密：密文和密钥不能随意放在一起

如果客户端把数据加密后，又把解密密钥放在同一个普通配置目录里，复制整个目录的人仍可能低成本解密数据。

普通安装版更合理的方式是：

```text
本地数据库：保存密文
系统安全存储：保存或保护本地数据密钥
```

macOS 可以使用 Keychain，Windows 可以使用系统提供的凭据保护能力。这样不能抵抗“设备已经被完全控制”这种最坏情况，但可以减少复制一个数据库文件就获得全部凭据的风险。

## 便携版为什么需要单独设计

Windows 便携版经常需要连同数据目录一起迁移。如果它完全依赖原电脑的系统安全存储，换电脑后可能无法解锁；如果为了便携而取消加密，风险又过高。

一种清楚的边界是让用户设置本地加密口令：

1. 客户端使用口令和随机 salt 派生本地密钥；
2. 数据目录保存密文、salt 和必要的 KDF 参数；
3. 不保存明文口令或明文数据密钥；
4. 迁移后由用户重新输入口令解锁。

它多了一步操作，但“谁掌握口令，谁才能解密”的边界容易理解。

## 云同步：应先在客户端加密

多设备同步意味着数据要离开本机。此时应该继续追问：

- 上传的是明文还是密文？
- 同步密码是否发送给服务端？
- 服务端是否拥有解密能力？
- WebDAV、S3、iCloud 等第三方存储是否使用相同加密方式？
- 多设备同时修改时如何处理冲突？

如果同步数据在客户端加密后再上传，服务端只承担存储和传输职责，就不需要接触服务器凭据的明文。

```text
用户口令 → 客户端派生密钥 → 本地加密 → 上传密文
```

这种方式的直接代价是：如果用户丢失同步密码，服务端通常也无法帮助恢复明文。

## “可以找回所有数据”可能与端到端加密冲突

普通网站账号能够重置密码很正常。但如果一个产品同时声称：

- 服务端无法解密同步数据；
- 用户丢失同步密码后，客服仍可以恢复全部服务器凭据；

这两个承诺通常需要进一步解释。服务端如果能绕过用户口令恢复明文，就意味着它可能拥有额外的解密路径。

对服务器凭据而言，“忘记同步密码后无法恢复”并不方便，却可能是安全边界真实存在的结果。产品应该在用户启用同步时明确说明，并提醒用户自行保存恢复信息。

## 同步冲突也是安全与可靠性问题

公司电脑和家里电脑可能同时修改同一批资产。如果客户端静默用旧版本覆盖新版本，可能导致：

- 新增资产或命令片段丢失；
- 凭据回退；
- 端口转发与跳板配置被旧数据替换；
- 用户在错误的环境上执行操作。

检测到版本冲突后，至少应该让用户选择从远端恢复或用本地覆盖，而不是无提示地决定。

## AI 功能还要多问一层

带 AI 的 SSH 客户端可能读取终端输出、配置片段或日志。除了本地凭据，还应确认：

- 哪些终端内容会发送给模型；
- 用户能否控制最近输出的范围；
- API Key 保存在哪里；
- 是否支持用户自己的模型接口；
- AI 生成的命令是否会自动执行；
- 写入、删除、重启等操作是否需要确认。

AI 能否访问服务器，与它能否不经确认改变服务器状态，是两个不同问题。具体设计可参考 [Termark AI 助手的执行边界](./termark-ai-design)。

## 选择 SSH 客户端时的安全清单

- [ ] 密码、私钥和代理凭据不明文落盘
- [ ] 本地数据密钥不与密文随意放在同一普通文件中
- [ ] 便携版有明确的迁移与解锁机制
- [ ] 同步数据上传前在客户端加密
- [ ] 同步密码不发送给存储服务
- [ ] 产品明确说明服务端能否解密
- [ ] 忘记同步密码后的结果提前告知
- [ ] 同步冲突不会静默覆盖
- [ ] AI 上下文范围可以理解和控制
- [ ] 可能改变服务器状态的 AI 命令执行前可见
- [ ] 有清楚的安全问题报告入口

## Termark 当前公开的安全边界

Termark 是商业 SSH 客户端，其公开说明包括：

- 本地敏感字段加密保存；
- 普通安装版使用系统安全存储保护本地数据密钥；
- Windows 便携版使用独立的本地加密口令；
- 同步数据在客户端加密后上传；
- 同步密码不发送给服务端；
- 服务端保存密文，不负责解密；
- AI 对可能改变远端状态的操作保留确认步骤。

这些边界不能代替用户自身的设备安全、服务器最小权限、密钥轮换和备份策略。任何本地客户端在设备已经被完全控制时都无法承诺绝对安全。

如果这些安全取舍符合你的工作方式，可以继续了解 [Termark 跨平台 SSH 客户端](https://www.termark.app/zh-cn/ssh-client/)；如果你倾向于不让任何图形工具保存凭据，系统 OpenSSH 与受控的 `~/.ssh/config` 仍然是合理选择。
