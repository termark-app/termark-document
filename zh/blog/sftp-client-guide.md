# SFTP 客户端怎么选？

SFTP 客户端最基本的任务只有两个：把文件上传到服务器，或者从服务器下载文件。如果你一个月只做几次，系统自带的 `sftp`、`scp` 或任何稳定的图形工具都够用。

真正拉开差距的是日常排障。你在终端里找到日志目录，下载文件分析，修改配置，再上传并检查权限。终端和文件工具如果各管一套主机、凭据和目录，这几步会反复切窗口。

这篇文章不做产品排行榜，而是用真实任务判断一个 SFTP 客户端是否适合你的工作流。

## 先确认你需要的是 SFTP，不是 FTP

名字相似，协议并不相同：

- FTP 和 FTPS 使用自己的连接方式与端口；
- SFTP 运行在 SSH 连接之上，通常使用 SSH 的 22 端口；
- SFTP 可以复用 SSH 的密码、私钥、SSH Agent、跳板机和主机密钥校验；
- 服务器支持 SSH，不代表一定开放 SFTP 子系统，仍需检查服务端配置。

如果你的服务器只开放 SSH，SFTP 通常比另外部署 FTP 服务更省配置。选择客户端时，也要确认它支持你现有的 SSH 认证方式，而不只是“用户名 + 密码”。

## 场景一：上传配置文件

常见任务是把本地修改后的 `nginx.conf`、Compose 文件或应用配置上传到服务器。这里至少要检查：

1. 上传同名文件时，客户端是否明确提示覆盖；
2. 能否跳过、覆盖或为冲突文件改名；
3. 传输失败后是否保留清楚的错误原因；
4. 是否能看到每个任务的来源、目标、进度和状态；
5. 是否支持文件夹传输，而不需要手工逐个选择文件。

上传配置前最好先备份旧文件。图形界面不会降低覆盖生产配置的风险，它只是把动作换成按钮。

## 场景二：下载日志并继续排查

排查服务问题时，目录经常在终端中才确定：

```bash
systemctl status nginx
journalctl -u nginx -n 100 --no-pager
cd /var/log/nginx
ls -lh
```

如果 SFTP 与终端是两个独立工具，你还要重新找到同一台服务器和 `/var/log/nginx`。支持终端目录跟随的客户端可以根据当前 shell 目录更新文件面板，减少找错主机或目录的机会。

Termark 的目录跟随不是靠猜测终端标题。桌面端会跟踪终端当前目录，并允许按主机单独启用或关闭。配置方式见 [SFTP 目录跟随文档](https://docs.termark.app/zh/usage/sftp-cwd-tracking)。

目录跟随也要允许手动控制。如果你正在浏览另一个目录，不应该因为终端执行了一次 `cd` 就强制打断当前文件操作。

## 场景三：在线编辑与本地程序编辑

小型文本文件适合内置编辑器，例如：

- Nginx 站点配置；
- systemd unit；
- `.env` 示例；
- Docker Compose 文件；
- Shell 脚本。

需要检查编辑器能否识别未保存状态、处理上传冲突，并在关闭标签前提醒。对于较大的配置或需要语言工具支持的文件，本地编辑器更合适。

Termark 桌面端 v1.4.0 增加了“使用本地程序编辑远程文件”：应用先准备本地编辑副本，用配置的本地程序打开，并负责远程编辑会话的生命周期。这个能力有明确的源码实现和版本记录，不是规划中的功能。

无论使用哪种编辑方式，都要留意远程权限。SFTP 以当前 SSH 用户身份读写文件；用户没有权限时，编辑器不能凭空获得 `sudo`。更稳妥的流程是先上传到用户可写目录，再在终端中审查并使用受控命令移动文件。

## 场景四：本地与远程双栏传输

双栏布局适合频繁在本机和服务器之间传文件。一个可用的双栏 SFTP 工作区应当让两侧独立选择资产：

- 左侧可以是“此设备”的本地文件；
- 右侧可以是 SSH 主机或 NextTerminal 资产；
- 两侧都能单独改变目录；
- 传输任务明确记录来源会话、目标会话和路径。

Termark 当前桌面源码中的 SFTP 工作区默认把左侧设置为本机文件，右侧可选择本地主机或 NextTerminal 资产。传输任务也区分来源与目标会话。这说明它不是在终端旁嵌入一个简单文件列表，而是独立的双栏文件工作区。

## 文件夹和大量文件怎么传

大量小文件逐个通过 SFTP 传输时，往返开销会很明显。有些客户端会提供打包流或并行传输模式，但这类加速需要同时考虑：

- 服务器是否有足够临时空间；
- 中断后如何清理临时文件；
- 软链接和文件权限如何处理；
- 失败时能否定位到具体文件；
- 加速模式是否属于付费功能。

Termark 当前源码同时包含标准 SFTP 与 `tarStream` 传输模式；强制加速模式会检查授权。因此文章不把“加速传输”写成免费通用能力。

如果你只传一个配置文件，标准 SFTP 更容易理解。只有目录很大、文件很多时，加速模式才值得测试。

## 排序、隐藏文件和文件信息

这些细节看起来小，日常用得很多：

- 文件夹应排在普通文件前面；
- 文件名最好采用自然排序，避免 `file10` 排在 `file2` 前；
- `.env`、`.ssh` 等隐藏文件需要可切换显示；
- 应能查看文件大小、修改时间、权限和链接类型；
- 刷新目录不应丢失当前路径；
- 面板暂时隐藏时完成上传，重新打开后应该刷新列表。

Termark 桌面端当前实现会先过滤隐藏文件，再按“目录优先 + 文件名自然排序”显示；v1.1.5 增加文件信息查看，v1.3.0 修复了面板隐藏期间上传完成后列表不刷新的问题。

## 认证和复杂网络

SFTP 复用 SSH，所以客户端至少要覆盖你实际使用的认证和网络路径：

- 密码和私钥；
- 带口令的私钥；
- SSH Agent；
- keyboard-interactive；
- OTP 自动交互；
- 单级或多级跳板机；
- HTTP 和 SOCKS5 代理；
- 主机密钥校验。

Termark 桌面端 v1.4.0 加入主机 OTP 自动交互认证，并增强多跳连接的认证重试；v1.3.0 修复 SSH Agent 多密钥认证；这些更新同样影响建立 SFTP 会话时的连接能力。

## 手机端 SFTP 适合做什么

手机 SFTP 适合临时查看、下载日志、上传一个修复文件或编辑小型文本。它不适合长时间整理大量目录。

Termark 移动端当前已经实现：

- 文件和目录列表；
- 新建目录；
- 重命名和删除；
- 显示或隐藏点文件；
- 文本预览和编辑，预览上限为 1 MiB；
- 上传、下载和传输中心；
- 传输取消与状态管理。

这些能力来自当前 `termark-app` v0.1.17 源码。移动端文章仍应把它定位成应急入口，而不是替代桌面文件管理。

## 试用 SFTP 客户端时完成这组任务

不要只看能否连上服务器。拿一台测试机完成下面的操作：

- [ ] 使用密码、私钥或 SSH Agent 登录；
- [ ] 经过跳板机打开 SFTP；
- [ ] 显示 `.env` 等隐藏文件；
- [ ] 上传一个与远程同名的文件，检查冲突提示；
- [ ] 下载一个目录，观察失败任务如何显示；
- [ ] 在线编辑一个文本文件，确认未保存提示；
- [ ] 使用本地编辑器打开远程文件；
- [ ] 在终端中切换目录，检查 SFTP 是否按预期跟随；
- [ ] 查看文件权限、大小和修改时间；
- [ ] 中断网络后重新连接，确认当前目录是否保留；
- [ ] 验证删除操作是否有明确确认；
- [ ] 确认哪些能力属于 Free，哪些需要 PRO。

## Termark 适合什么 SFTP 工作流

Termark 适合经常在终端排查和文件传输之间切换的用户。桌面端把本地文件、SSH 主机和 NextTerminal 资产放进双栏 SFTP 工作区，并提供传输队列、目录跟随、内置编辑与本地程序编辑。

如果你只偶尔传一个文件，命令行 `scp` 或已有工具不必更换。如果你经常下载日志、调整配置、经过跳板机连接内网服务器，可以从 [Termark SFTP 客户端页面](https://www.termark.app/zh-cn/sftp-client/)下载试用，再对照本文的任务清单判断是否适合。
