# SSH 客户端怎么选？Windows、macOS、Linux 工具选择指南

搜索“SSH 客户端推荐”时，最容易得到一串工具名称。但 SSH 客户端没有脱离场景的“最好”：偶尔连接一台 VPS、每天管理几十台服务器、需要经过跳板机、要在手机上处理告警，选择标准完全不同。

与其先问哪个软件最强，不如先回答三个问题：

1. 你在哪些系统上工作？
2. 连接之后最常做什么？
3. 你愿意把凭据和同步数据交给谁？

这篇文章不做简单排名，而是给出一套可以自己验证的选择方法。

## 先判断你是否真的需要图形 SSH 客户端

如果你只管理一两台服务器，并且已经熟悉 `~/.ssh/config`、系统终端和 `scp`，系统自带的 OpenSSH 很可能已经够用。它可控、可脚本化，也容易与现有命令行工作流组合。

图形 SSH 客户端的价值通常出现在这些场景：

- 主机越来越多，需要分组、搜索和统一管理；
- 密码、私钥、代理和跳板机配置开始重复；
- 经常在终端与 SFTP 工具之间切换；
- 需要保存端口转发规则、命令片段或会话记录；
- 在 Windows、macOS、Linux 或手机之间切换；
- 希望 AI 帮忙解释日志和生成命令，但不能自动操作生产服务器。

如果这些问题并不存在，不必为了“功能多”换工具。

## Windows：先看工作流，不要只看功能数量

Windows 用户常见选择包括系统 OpenSSH、PuTTY、Xshell、MobaXterm、Tabby、Termius 等。选择时可以先看：

- 是否需要 SFTP、RDP、X11 等远程工具集合；
- 是否依赖 Windows 便携版；
- PowerShell、WSL 与普通 SSH 会话是否都要管理；
- 安装包签名、自动更新和安全软件误报说明是否清楚；
- 数据目录和卸载行为是否可预期。

如果目标是一个围绕 SSH、SFTP、端口转发和资产组织的桌面工作区，可以查看 [Termark Windows SSH 客户端页面](https://www.termark.app/zh-cn/windows-ssh-client/)；如果偏好完全命令行的方式，系统 OpenSSH 通常更直接。

## macOS：系统终端已经很好，图形工具要提供额外价值

macOS 自带 OpenSSH，搭配 Terminal、iTerm2 或其他终端已经能覆盖许多工作。图形客户端至少应该在以下方面提供明确收益：

- 把服务器、凭据、跳板机和代理组织起来；
- 内置 SFTP，不必单独打开文件工具；
- 支持 Apple Silicon，安装包完成签名和 notarization；
- 多设备同步时说明数据是否在客户端加密；
- 快捷键和窗口行为符合 macOS 使用习惯。

如果只是需要更好的终端外观，没有必要把主机凭据迁移到另一套系统。

## Linux：原生命令行优先，桌面工具更适合统一资产

Linux 用户通常已经拥有成熟的 OpenSSH 工作流。桌面客户端更适合这些需求：

- 同时维护个人电脑、工作站和其他平台；
- 希望把终端、SFTP 和资产树放进统一界面；
- 需要可视化管理代理、跳板机和端口转发；
- 想减少重复录入凭据和命令片段。

选择 Linux 客户端时，还要确认发行版、CPU 架构、安装格式和桌面环境支持，而不是只看到“支持 Linux”四个字。

## 十项真正影响长期使用的检查

### 1. 终端基础体验

检查中文宽度、复制粘贴、快捷键、全屏程序、搜索、分屏和网络断开后的恢复。终端稳定性比首页截图重要。

### 2. 认证方式

除了密码和私钥，还可能遇到私钥口令、SSH Agent、keyboard-interactive、动态口令和堡垒机交互。先确认自己的环境需要哪些能力。

### 3. 跳板机与代理

真实连接路径可能是：

```text
本机 → HTTP/SOCKS5 代理 → 跳板机 → 内网服务器
```

确认工具能否复用跳板机和代理配置，而不是让每台主机重复填写。

### 4. 老旧服务器兼容

历史设备可能仍需旧主机密钥算法或 GBK 编码。合理的客户端应保持安全默认值，同时允许用户仅为特定资产启用兼容选项。

### 5. SFTP 是否融入终端工作流

只判断“有没有 SFTP”不够。还要看文件夹传输、远程编辑、权限处理，以及能否跟随终端当前目录。

### 6. 端口转发

如果经常访问内网数据库或调试服务，保存和复用本地/远程转发规则能减少临时拼命令的错误。

### 7. 多服务器操作

批量执行的重点不是同时发送命令，而是能否确认目标主机、分别查看输出、识别失败并避免把测试命令发到生产环境。

### 8. 凭据如何保存

不要满足于“已加密”三个字。继续确认：

- 敏感字段是否明文落盘；
- 本地数据密钥保存在哪里；
- 便携版如何解锁；
- 卸载或迁移后数据如何处理。

更完整的判断方法见 [SSH 客户端凭据安全边界](./ssh-credential-security)。

### 9. 多设备同步

需要确认上传的是明文还是密文、服务端能否解密、同步密码丢失后会发生什么，以及多设备冲突是否静默覆盖。

### 10. AI 是否保留执行边界

AI 可以解释错误、生成命令和整理排查步骤，但服务器上的写入、删除、重启和权限变更应在执行前对用户可见。Termark 的设计取舍详见 [AI SSH 助手为什么不应该默认全自动](./termark-ai-design)。

## 按使用场景做最后选择

| 场景 | 更值得优先考虑 |
| --- | --- |
| 偶尔连接一台 VPS | 系统 OpenSSH、简单终端工具 |
| Windows 远程工具需求复杂 | 集成度高的 Windows 远程工具箱 |
| 多平台共享资产 | 明确支持多端和加密同步的客户端 |
| 终端与文件操作频繁切换 | 终端与 SFTP 共用资产上下文的客户端 |
| 多级跳板和代理 | 可复用复杂连接路径的客户端 |
| 生产服务器使用 AI | 命令可见、写操作需要确认的 AI 助手 |
| 手机应急处理 | 有原生移动端并说明后台限制的客户端 |

## 一份可以直接使用的选择清单

试用任何 SSH 客户端时，可以逐项验证：

- [ ] 我的操作系统和 CPU 架构有正式安装包
- [ ] 常用认证、代理和跳板路径可以连通
- [ ] 中文、复制粘贴、快捷键和全屏程序正常
- [ ] SFTP、端口转发和命令片段符合实际工作流
- [ ] 本地凭据与同步数据的加密边界说得清楚
- [ ] 免费版和付费版边界明确
- [ ] 能导入或复用现有资产，而不是全部重录
- [ ] AI 执行命令前保留用户确认
- [ ] 文档、更新日志和问题反馈入口持续维护
